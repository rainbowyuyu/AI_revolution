# 第二章 V18 视频工程

这里保存第二章《从识别到创造》的可编辑 Remotion 工程：**1920 × 1080、30 fps、54,724 帧，约 30 分 24 秒**。当前入口是 `src/index-v18.tsx`，合成 ID 为 `Chapter02-V18-1080`。时间线、字幕、教学动画和实验图像已纳入仓库；原始音视频、角色素材、论文页面和字体按外部清单恢复。

这不是下载源码后无需素材就能生成整片的包。`npm run check` 只验证 TypeScript；它通过不表示音视频、字体或论文图已经齐备，也不表示已重新渲染并审看整片。

## 工程保留了什么

| 位置 | 用途 |
|---|---|
| `src/index-v18.tsx`、`FilmV18.tsx` | 当前合成入口与 V18 完整音频母带 |
| `FilmV16.tsx` | 经过修正的字幕、背景镜头与版式组合；V18 调用时关闭其中的 V16 音轨 |
| `TeachingV15.tsx`、`VisualV15.tsx`、`ScenesV15.tsx`、`opus-v15/` | 实验可视化、教学图解、踏雪角色镜头 |
| `timeline-v15.json`、`captions-v16.json` | 59 段时间线与 524 条字幕；V18 沿用已检查的画面和字幕时序 |
| `voice-visual-anchors-v15.json` | 文字与画面标记的时间码，不含任何声音样本 |
| `papers-v4.json`、`PaperV8.tsx` | 论文出处、原页坐标与放大镜头；论文图另行恢复 |
| `results/` | 已保存的二维实验结果与 MNIST 图像；源码直接导入其中的 JSON |
| `public/experiments/features-v2/`、`prediction/` | 18 张特征图与 15 张噪声预测/估计图 |
| `assets/video-manifest.json` | 外部素材的相对路径、字节数与 SHA-256 |

按 V18 依赖收录 15 个 TSX 和 12 个 JSON，没有打包 V1–V18 全套历史入口。`PaperV8` 的类型引用已接到当前 `TeachingV15`，避免仅为类型拉入整棵旧版工程；未被当前调度使用、且引用已不存在素材的旧 `PearlScene` 分支已移除。组件文件中的版本号表示来源，并非推荐启动版本。

`pearl-intro`、`gan-pearl`、`return-pearl` 等旧内部 ID 与部分路径仍用于匹配时间线和素材，保留它们是为了兼容；当前画面角色为小狗踏雪。改这些 ID 时需要同步修改所有引用。

## 安装与编辑

建议 Node.js 22、npm 和 Python 3.11 或更新版本。在 `chapters/02-generation` 下运行：

```sh
npm ci
npm run check
npm run assets:prepare
```

`assets:prepare` 把仓库内 `results/digits/` 的 50 张图恢复到 Remotion 的 `public/experiments/digits/`。这个派生目录不需要再次提交 Git；大型 JSON 直接从 `results` 导入，不复制两份。

完整预览前，使用你有权使用的原始素材目录恢复外部文件。参数指向原制作工程中的 `public` 目录，目录下面应直接包含 `audio/`、`character/`、`media/` 等子目录：

```sh
python scripts/prepare_assets.py --source-public /path/to/original/public
npm run assets:check
npm run studio
```

恢复脚本检查原文件的体积和 SHA-256；已有文件哈希不符时会报告并保留，避免覆盖本地修改。脚本不会下载素材，也不读取密钥或访问制作服务。

需要修改旁白时，先在你自己的授权声音流程中生成新的母带并重新校验字幕。仓库只登记 V18 混音母带 `public/audio/v18/master.wav`，没有收录私人 TTS 参考、声音模型或逐句合成服务配置。

## 渲染入口与素材边界

恢复并核验外部文件后：

```sh
npm run render
npm run still -- --frame=1177
```

默认渲染直接指向 V18，输出到忽略的 `output/` 目录。它重新渲染整条时间线，不依赖原制作机的分段复用流水线。完整渲染可能耗时较长，本次整理没有重新渲染或重新生成声音。

外部清单共 **165 项，1,642,062,265 字节（约 1.53 GiB）**，包含当前工程所需的原视频、角色与噪声图、5 张时序示意图、论文整页/局部图、两种中文字体和 V18 混音母带。清单按当前媒体表、数据文件和源码中有界动态路径建立；未把历史分段、成片和私人声音参考作为依赖。

`media-v15.json` 中少量 `nativeVideo`、`sourceVideo` 等字段保留来源信息；渲染只读取当前 `video`，或在 `ready=false` 时读取 `image`。因此这些溯源字段中的每一条旧路径并不都是要恢复的依赖。

素材内容、角色参考、商标和声音的使用权限由相应权利人保留。论文出处及权利说明在 `papers-v4.json` 中，保留作者、题名、年份、官方论文地址、页码和 SHA-256；引用不代表取得开放再分发许可。两种中文字体的[实际版权与官方来源](../public/fonts/NOTICE.md)及 [SIL Open Font License 1.1 正文](../public/fonts/OFL.txt)随 Git 保存，恢复或再分发字体时应保留这些说明。实验图只支持其实际实验范围，不能当作训练出踏雪角色的证据。

## 可选帧缓存

为了让 GitHub 包便于恢复，`FrameVideoV15.tsx` 默认 `USE_FRAME_CACHE = false`，从原视频以 `OffthreadVideo` / `Freeze` 解码到最接近的源帧。它保留时序和镜头来源，但与历史 JPEG 缓存使用的向下取整、编码压缩可能存在逐帧像素差异，不承诺逐像素复现 V18 交付母版。

`frame-cache-v15.json` 只保留当前源码引用的 **95 条映射、52,161 帧**，并登记对应源视频的 SHA-256，不再携带 234 条历史缓存映射。缓存本身不随 Git 上传，也不是默认启动的必需项。

如需要大量逐帧访问，先自行安装 FFmpeg、恢复原视频，再运行：

```sh
python scripts/build_frame_cache.py
```

脚本按 30 fps 生成 JPEG，验证原视频哈希与预期帧数；已有完整缓存会保留，遇到半成品目录会停止。成功后，可把 `src/FrameVideoV15.tsx` 中的 `USE_FRAME_CACHE` 改为 `true`。重编码生成的 JPEG 不承诺与历史缓存像素一致。需要精确历史母版时，应使用原始审核过的帧缓存和制作环境，并重新做音画检查。

## 维护素材清单

改变源码中的动态路径规则时，同时更新 `scripts/build_video_manifest.py` 的有界展开规则。拥有完整授权素材的维护者可以重新生成清单：

```sh
python scripts/build_video_manifest.py --source-public /path/to/original/public --trim-cache
```

该工具仅输出相对素材路径、文件体积和内容哈希，不记录本机绝对路径、服务端地址、临时下载 URL 或凭据。修改已发布媒体内容后，重新生成哈希并更新说明，再检查所有相关时间线与字幕。
