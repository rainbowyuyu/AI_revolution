该检查重算分词、注意力、统计续写、采样和公式例子，检查CLIP已保存结果的矩阵、概率、排序、输入文件与哈希；不下载权重、不运行CLIP推理。报告写入 `runs/ch03-check-<UTC>/`。报告中的 `passed` 应为 `true`。

## 实验一：分词、注意力与下一字符预测

以下 `python` 代表上一步虚拟环境的解释器。未激活环境时，使用其完整相对路径替换。

```sh
python chapters/03-language-multimodal/experiments/run_mechanisms.py --out-dir runs/ch03-mechanisms
python chapters/03-language-multimodal/experiments/check_evidence.py --run-dir runs/ch03-mechanisms
```

`--out-dir` 相对当前工作目录，必须是不存在或为空的目录。不传时自动在仓库 `runs/` 下创建带UTC时间的目录；再次运行可以换名，不能覆盖 `results/` 中冻结证据。

| 输出 | 怎么看 |
|---|---|
| `tokenization.json` | 14次合并的片段与频次、词表、输入的切分/编号与还原 |
| `causal_attention.json` | 4×2的Q/K/V、4×4分数/权重、遮罩与最终输出 |
| `next_token.json` | 训练/留出语料、平滑、候选分布、NLL和温度示例 |
| `sampling_trace.json` | 种子12逐步产生的随机数、完整分布、选中字符和新前缀 |
| `formula_examples.json` | 六维输入经过6×2矩阵的投影、六词元因果注意力、归一化与交叉熵例子 |

### 从一个小操作开始

- 看分词：找到 `merges[0]`，数一数这一对片段为何被选中；把 `examples` 的词元拼回原文。
- 算注意力：取一行Q与所有K做点积，除以维度平方根，把未来位置设为负无穷，经过softmax后加权V。
- 看续写：找到前缀“雨后的红伞”，比较每个候选的概率；再看固定种子在温度0.5、1、1.5下的完整采样轨迹。
- 看训练目标：对比正确目标概率为0.1和0.8时的 `-log(p)`，理解预测变化怎样对应损失变化。

修改语料或参数后，可以生成你自己的新结果；与原视频的冻结证据不同属于预期情况。`check_evidence --run-dir` 是复现核对，不要求任意新实验都与原数据相同。

计数基线只看前两个字符，语料为人为构造的64句。它便于观察条件分布，没有训练Transformer。注意力与投影参数是教学设定，计算为精确实算，不能把权重图当作某个训练模型的语义解释。

## 实验二：CLIP图文检索

另建可选环境。首次执行需要下载 `openai/clip-vit-base-patch32` 的模型与处理器；revision固定为 `3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268`。代码固定在CPU执行，不需要GPU或付费API。

```powershell
py -3.12 -m venv .venv-ch03-clip
.\.venv-ch03-clip\Scripts\python.exe -m pip install -r chapters/03-language-multimodal/requirements-clip.txt
.\.venv-ch03-clip\Scripts\python.exe chapters/03-language-multimodal/experiments/run_clip.py --out-dir runs/ch03-clip
```

Linux/macOS用 `python3 -m venv .venv-ch03-clip`，解释器替换为 `.venv-ch03-clip/bin/python`。

已有相同revision缓存时，可以加 `--local-files-only` 禁止下载；没有缓存时会明确失败，不会自行改模型版本。Torch安装包因平台可能较大；仅看结果和运行机制实验不需要安装这一组依赖。

输入是 [assets/inputs](../assets/inputs/) 中三张原字节保留的生成候选图，查询为五条英文短句；视频用中文解释含义。为了沿用CLIP模型的训练语境，不把查询翻译后声称是相同实验。

程序会分别执行两种预处理：

1. 官方默认短边缩放和224×224中心裁剪。
2. 先用CLIP均值色填成正方形以保留全图，再走同一官方处理器。

输出 `clip_retrieval.json` 保存完整五条查询的相似度、logit、候选集softmax与排序；`clip-inputs/` 保存六张去归一化后的实际模型输入。对比红车的两张输入，再看 `red_car` 查询的排序。

此次整理没有重新执行CLIP模型推理。原始冻结结果来自已记录的CPU推理；跨平台重跑余弦分数建议按绝对容差 `5e-5` 比较，不要求浮点末位逐字节相同。重新取得模型结果与离线检查证据是两个不同步骤。
