# 第三章视频工程：语言连接万物

这里保存第三章 V10 的可编辑 Remotion 工程。它从“一张红伞靠在蓝门边的照片”出发，串起分词、向量、注意力、Transformer、语言预测、图文检索、指令与偏好、多模态输入，并保留结尾逐篇论文讲解。

**仓库包含动画代码、讲稿与字幕时间线、小型教学图片；不包含完整成片所需的大媒体。克隆后可以阅读和修改源码、运行类型检查；恢复外部素材后才能完整预览或渲染。**

## 从原工程离线恢复

如果你持有原制作工程的 `public` 文件夹，把它的**实际路径**传给 `--source`。路径可以包含空格，需要保留引号。示例中的尖括号是待替换内容，不是可直接执行的真实路径。

先检查仓库已有小图：

```bash
node scripts/restore-video-assets.mjs --check --bundled-only
```

再验证原媒体是否齐全，不复制文件：

```bash
node scripts/restore-video-assets.mjs --source "<原制作工程>/public" --dry-run
```

实际恢复并复查：

```bash
node scripts/restore-video-assets.mjs --source "<原制作工程>/public"
node scripts/restore-video-assets.mjs --check
```

脚本对每个待复制文件先验证字节数与 SHA-256，全部来源检查通过后才开始复制，复制完成还会核对校验值。已有文件与清单一致则跳过；已有文件不同会报告冲突，不会默默覆盖。确认要替换自己的本地副本时才增加 `--overwrite`。脚本不下载、不生成图片或配音，不读取凭据，也不删除旧素材。

**没有原媒体的人仍可学习和修改动画与实验，但无法仅凭清单恢复原成片。** 论文 URL 与字体上游链接用于定位出处，不承诺下载得到的任意版本与原文件 SHA-256 相同。若改用自己的素材，请同时修改引用与清单中的校验值；图片尺寸、论文聚焦坐标、视频时长以及音画同步也需要重新核对。

## 与原生产工程的明确差异

原版 `Film.VideoFrame` 优先读取大量逐帧 JPEG，`OverviewScene.Photo` 也有一处直接缓存读取。本公开工程把两处都改为 **`Freeze` 与 `OffthreadVideo` 直接解码选定 MP4**，保留原整数帧号、循环范围与播放速度。不需要复制 JPEG 缓存，也不需要运行缓存构建脚本。

这一调整减小工程体积，但直接解码可能更慢；解码结果和原 JPEG 二次压缩缓存不保证逐像素一致。时间线、动画数据、字幕、论文摄影机区域和最终混音引用保持当前版本。这里没有宣称重新渲染已经与生产成片完成逐帧对比。

发布时还移除了 TTS 原始音频绝对路径、逐句生产文件、服务任务 ID、内部质检路径及旧版制作元数据。API 客户端、语音模型、声音参考、训练权重、完整音视频、字体和 PDF 均不在此最小工程内。

## 建议的维护顺序

1. 改讲稿时先改 `timeline.json` 中对应单元，保持单元 ID 稳定；时长改变后同步字幕与镜头帧区间。
2. 改教学画面时优先编辑 `visualizations/v10` 内对应组件。动画继续由帧号驱动，数值变化保留对象并插值。
3. 改实验结果时同时维护真实输出与画面所读取的证据，避免只改画面数字。
4. 换环境或转场时修改 `media.json`，核对 `frames`、`playbackRate` 和两端动作。
5. 换论文截图时保持 PDF 坐标、页面宽高与 `cameraBox` 一致。
6. 最后运行类型检查、素材校验，检查代表帧和完整预览，再决定是否导出更高分辨率。
